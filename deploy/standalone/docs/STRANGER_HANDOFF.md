# 陌生人交付操作手册 / Handoff drill

目标是验证：一个没有参与 IMBoy 开发的人，只依靠这份 ZIP 和事先列明的现场信息，能否在获准的干净服务器上完成社区版安装，并如实记录未完成项。

这是一份现场操作方法，**制包与离线回归不执行真实陌生人服务器演练**。实际结果填入 [验收结果记录模板](ACCEPTANCE_TEMPLATE.md)。

## 1. 演练开始前的交接

交付者提供：

- 本 ZIP、外层 SHA-256 校验值、包内 `SOURCE_COMMIT` 与文件来源清单，以及本次发布说明。
- 已批准的测试服务器，明确是新实例还是已有实例，以及允许执行的维护窗口。
- 五域、入口 IP、DNS / 防火墙权限、证书邮箱、镜像版本与拉取权限。
- 独立清理数据库账号的开通负责人；凭据通过客户认可的安全渠道交接。
- 两个验收客户端、真实开户或测试账号获取方式，以及本次承诺验收的功能范围。
- 故障联系人、停止条件、备份位置和回退负责人。

操作人只获取这些材料。不要提供完整源码仓库、开发环境、作者电脑上的历史配置或聊天中未落入材料的安装诀窍。若演练必须依赖额外口头指导，将该指导记入“材料缺口 / 人工干预”，再补充到交付说明。

条件不足时记为 `BLOCKED`，写明缺少什么、谁补齐。不要把环境缺失记成通过，也不要为继续演练而临时开启开发认证、忽略证书或改用未知镜像。

## 3. 操作顺序

| 阶段 | 依照哪份材料 | 完成证据 |
|---|---|---|
| 收包与校验 | 根目录交付说明；`bash scripts/check_delivery.sh` | 外层校验值、包内校验输出、源码基线 |
| 工具准备与离线复核 | INSTALL 第 5 节；`bash scripts/run_offline_checks.sh` | 工具版本、统一离线回归日志与退出码 |
| 现场准备 | INSTALL 第 6–7 节 | DNS 比对、网络条件、客户配置完成记录 |
| 安装 | INSTALL 第 8 节 | 完整安装日志、退出码、失败阶段（若有） |
| 清理账号 | DB_CLEANUP_ACCOUNT.md | 实际账号存在、最小成员资格、TCP 密码登录结果 |
| 基础设施验收 | ACCEPTANCE_COMMANDS.md | 9 服务、健康、证书、迁移、镜像 digest |
| 管理员与业务 | ACCEPTANCE_COMMANDS.md | 首次初始化、登录、双向消息、附件往返等结果 |
| 重复安装保护 | ACCEPTANCE_COMMANDS.md 的独立演练步骤 | 密钥 / 数据保护证据、再次安装退出码、业务复验 |
| 收尾交接 | ACCEPTANCE_TEMPLATE.md | PASS / FAIL / BLOCKED / NOT_RUN / N/A 分项记录及签字 |

开始与结束时间使用北京时间，保留时区；实际服务器日志若使用 UTC，记录对应关系。耗时目标由本次交付双方预先约定，不用“几分钟”之类未验证承诺代替计时。

## 4. 发生失败时怎么做

1. 记录当前阶段、原命令、退出码和第一条关键错误，先保存现场。
2. 查 [TROUBLESHOOTING.md](TROUBLESHOOTING.md)，只执行与当前症状对应的检查。
3. 保留已生成的 `.env`、RSA、数据库、Garage 和证书目录。没有明确恢复方案时，不删除数据、不重置密码、不重新复制模板。
4. 若需要交付者介入，记录介入人、耗时、具体操作、原因和应补入文档的位置。
5. 修复后复验受影响的步骤。安装器退出 0 仍要继续业务验收；已执行但失败的步骤保持 `FAIL`，直到有新的成功证据。

同时记录“由材料即可解决”和“必须依赖作者额外指导”的区别，便于判断交付材料是否足够独立。

## 5. 记录与交接规则

| 状态 | 含义 |
|---|---|
| `PASS` | 实际执行，满足该项预期，并有时间、环境和证据 |
| `FAIL` | 实际执行，输出或行为不符合预期 |
| `BLOCKED` | 缺少明确的环境、账号、权限、设备或前置步骤，无法执行 |
| `NOT_RUN` | 尚未执行；不能由其他步骤推定通过 |
| `N/A` | 不在本次已约定的交付范围，并写明原因及确认人 |

安装日志和数据库备份可能包含敏感信息。原始证据保存在客户受控目录，限制权限；给交付方的副本先去除密码、token、私钥、带签名的附件 URL、真实手机号和业务内容。不要把整个 `.env` 或 `docker inspect` 的环境变量输出放进工单。

## 6. 最终交付判定

只有全部必需现场项通过，所有 FAIL 已解决，所有 BLOCKED / NOT_RUN 均已按交付约定处理，才能签署本次验收。可选功能未启用可以记 `N/A`，不能写成“已通过”。

独立文件包通过离线检查，说明材料可以完整携带并执行相关检查；它不自动等于镜像可用、真实安装成功或客户业务可用。未完成的项目保留负责人和下一次验证条件，交给后续现场验收继续处理。
