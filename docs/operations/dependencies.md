# Imboy 运行依赖与基础服务

> Last Updated: 2026-03-08  
> Status: 长期运维文档  
> Scope: 交付、开发、部署阶段涉及的基础服务与外围组件说明  
> Note: 实际交付环境以项目部署清单为准；本文档用于说明默认依赖边界，不直接等同于环境实施单。  
> Related docs: `docs/guides/deployment.md`, `docs/architecture/database-access.md`, `docs/operations/security.md`

## 1. 文档目的

本文档用于说明 `Imboy` 当前交付、开发、部署过程中依赖的基础服务与外围组件。

它回答三个问题：

1. 系统运行至少依赖哪些基础设施；
2. 哪些能力已经使用，哪些只是可选或预留；
3. 交付时哪些依赖需要明确告知客户或实施方。

## 2. 当前核心依赖

### 2.1 数据存储

- `PostgreSQL 18`：主数据库，当前核心业务数据以 PostgreSQL 为准；
- `PostGIS`：地理位置相关能力依赖，如“附近的人”等空间查询；
- `pg_jieba`：中文分词扩展，用于开放搜索 / 用户搜索类场景；
- `pgvector`：向量能力预留，当前是否启用应以实际交付方案为准；
- `timescaledb`：时序能力预留，当前不是基础交付默认强依赖；
- `pgroonga`：检索能力预留，当前是否启用应以环境配置为准。

### 2.2 接入层与运行环境

- `Nginx`：反向代理、HTTPS、WebSocket 转发；
- `Linux`：默认部署运行环境；
- `Docker`：可作为部署与交付承载方式之一，但不是唯一方式。

### 2.3 文件与媒体

- 文件存储当前按交付环境选择具体方案；
- 历史 `go-fastdfs` 方案可视为可选实现，不再作为仓库内固定样例配置；
- 正式交付时，上传地址、访问域名、授权方式应在项目部署环境中单独维护。

### 2.4 缓存与进程内能力

- `mnesia`：当前不是直接对外交付依赖；
- `zotonic/depcache`：当前项目存在使用；
- 如交付环境引入额外缓存层，应在实施方案中单独说明。

## 3. 当前非强依赖 / 预留能力

以下服务当前不应被表述为“一期交付必须包含”：

- `RabbitMQ`
- 第三方推送服务（Apple / 华为 / 极光等）
- 地图服务的多厂商切换
- 应用商店上架服务接入

这些能力是否纳入交付，应以版本范围、客户合同和实施方案为准。

## 4. 交付时建议明确说明的内容

实施或交付前，至少确认：

- 数据库版本与扩展清单是否与目标环境一致；
- 是否需要 `PostGIS`、中文分词、向量或时序扩展；
- 上传与文件访问是否需要独立存储服务；
- 反向代理是否承担 HTTPS 与 WebSocket 转发；
- 是否需要第三方推送、地图、商店、内容安全等外部平台对接。

## 5. 不建议继续沉淀在通用仓库中的内容

以下内容不再建议以“环境绑定样例”形式长期存放在本仓库：

- 绑定具体域名、IP、证书路径的 `nginx` 配置；
- 绑定具体对象存储 / 文件存储厂商的生产配置；
- 绑定某个客户环境的运维面板、机器账号、目录约定。

这类信息应保存在：

- 交付项目目录；
- 独立运维仓；
- CI / Secret / 配置平台。
