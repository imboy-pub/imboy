## 0. 一句话定位

在客户授权的单台服务器上，用 **10 个工作日**把 IMBoy 以**单节点 Docker Compose** 形态部署到客户环境，按[验收矩阵](./poc-single-node-acceptance-matrix-2026-08.md)逐项验证，产出可签字的验收记录，支撑 Go / Rework / No-Go 商业判定。

**交付边界 = 单节点**（2026-07-31 拍板，见 [edition-boundary.md](./edition-boundary.md) 关键工程约束 0）。集群、HA、多副本 Helm 配置**未经生产验证，不在任何售前/PoC 承诺内**。

## 1. ICP 信号（哪些客户画像适用）

PoC 只接同时满足以下信号的组织；任一"排除信号"命中即先转标准演示，不启动 PoC。

| # | 正向信号（命中越多越优先） |
|---|---|
| I1 | **数据必须留在自己可控环境**：合规、保密或主权要求使 SaaS IM（钉钉/飞书/Slack）不可接受 |
| I2 | **规模落在单节点带宽数量级**：约 ≤ 数百活跃用户，无多机房/异地容灾硬需求 |
| I3 | **有基础运维能力**：能提供一台 Linux 服务器（建议 4C8G 起）+ Docker 环境 + 两个解析到该机的域名 |
| I4 | **有真实协作场景可授权验证**：能指定一个主场景（如班级/课程协作、团队项目协作），并提供测试账号与脱敏样例 |
| I5 | **决策链短**：业务评审人、技术负责人、决策人可在 10 个工作日内到场复测 |
| I6 | **安全诉求明确**：E2EE、密码存储、附件授权访问属于采购考量而非加分项 |

| # | 排除信号 |
|---|---|
| E1 | 要求集群 / 高可用 / 多活 —— 当前不承诺，转为路线图沟通 |
| E2 | 要求信创目录 / 国密 SM 系列 / 等保认证背书后才肯进入验证 |
| E3 | 要求真实支付收款、生产支付回调联调 |
| E4 | 无运维能力且不接受托管式替代方案（服务器完全不可提供） |
| E5 | 要求把历史 IM 平台全量数据迁移一并纳入 PoC |

## 2. 10 工作日里程碑（按天拆，节奏与商业资料仓 PoC Runbook 对齐）

| 天 | 里程碑 | 我方动作 | 客户方配合 | 产出证据 |
|---|---|---|---|---|
| D1 | 场景与成功标准确认 | 固定主场景、角色、账号清单、验收范围 | 指定评审人/技术负责人/决策人；书面授权环境与脱敏材料 | PoC 说明 + 数据清单 + 风险清单 |
| D2 | 环境前置检查与单节点部署 | `preflight.sh` → `install.sh` 部署；记录 Release Identity 三元组 | 提供服务器、域名解析、`.env` 三变量（API_DOMAIN / ADMIN_DOMAIN / CERTBOT_EMAIL） | 版本指纹 + 部署记录 + 问题列表 |
| D3 | 业务对象配置（群/频道/项目空间） | 按主场景建群、频道、项目空间与成员角色 | 确认组织结构与可见范围 | 场景配置记录 |
| D4 | 流程配置（公告/资料/任务） | 配置公告、资料分发、任务/日程流程 | 提供 5–10 个样例流程或脱敏材料 | 场景配置记录（续） |
| D5 | 管理后台与治理配置 | Admin 登录、用户管理、E2EE 模式设定并**向客户披露两种模式差异** | 确认治理规则（谁能管谁、审计要求） | 治理配置记录 |
| D6 | 消息与附件验证 | 双账号 C2C/C2G、附件上传/下载全链路 | 提供两台目标真机（iOS/Android） | 测试记录 |
| D7 | 运维验证日 | 备份 → 恢复演练 → 升级/回滚演练（详见[运维操作链索引](../guides/operations/single-node-ops-chain-index-2026-08.md)） | 确认演练窗口（可造成短暂停机） | 运维验证记录（含耗时） |
| D8 | E2EE 专项验证 | required 模式真机收发 + 数据库密文取证 + compliance 模式披露确认 | 在目标真机操作；确认模式选择 | 设备与测试记录 |
| D9 | 种子用户试用与修复 | 至少 1 名真实种子用户试用；修复 PoC 范围内缺陷 | 组织试用、回收反馈 | 反馈表 + 缺陷清单 |
| D10 | 复测与评审 | 按验收矩阵逐项复核；输出结论 | 参加复测与 Go / Rework / No-Go 评审 | 验收矩阵执行记录 + [签字记录](./poc-customer-signoff-template-2026-08.md) |

> 客户环境、数据授权、设备或外部系统未就绪时，对应里程碑记 `blocked_external_dependency`，**不得用我方本地演示替代客户环境验收**。

## 5. 明确不包含项（Non-Goals）

以下各项**不在本 PoC 范围内**，亦不得在 PoC 沟通中作为承诺出现：

1. **集群 / 高可用 / 多副本**：路线图项，未经生产验证。
2. **信创国产化适配**（达梦/金仓/鲲鹏/UOS 等）：企业版方向，未交付。
3. **国密 SM2/SM3/SM4**：未交付。
4. **LiveKit 录制**（音视频会议录制）：未交付。
5. **真实支付与生产支付回调**：支付网关在社区部署形态固定关闭；外部支付网关收款/订阅计费为路线图项。
6. **历史 IM 平台数据迁移**、多节点扩容、正式 SLA、7×24 值守。

## 6. 报价假设（待验证假设，非报价）

> ⚠️ **本节全部数字均为"待验证假设"**，不是报价、不是价格承诺。正式报价以商业资料仓逐单确认的书面报价单为准；在获得付款或客户验收证据前，任何价格均不构成承诺（与 `imboy-commercial-hub` 使用规则一致）。

| 假设项 | 待验证内容（不含实价） | 验证方式 |
|---|---|---|
| PoC 收费模式 | 是否收取固定 PoC 服务费、是否可抵扣正式采购款 | ≥3 家目标客户访谈后定稿 |
| 正式版价格档位 | 三档（社区免费 / 专业 / 企业）的定价锚点与支付溢价是否成立 | 首批报价反馈 |
| 升级服务计价 | 1 年免费升级期后的延长方式 | 首批续约谈判 |
| 交付人天假设 | 10 工作日 × 交付人力配置是否可复用为标准交付包 | 本次 PoC 实测工时 |

## 7. 升级路径（PoC 之后如何转正式）

```
PoC 结论（四态）
├─ accepted  → 进入转正式评估
├─ rework    → 列修复项与复测日期，回到 D9/D10
├─ blocked_external_dependency → 挂起，客户侧条件就绪后恢复
└─ no-go     → 归档记录，不进入商务流程

accepted → 正式上线包（同时满足以下条件才建议启动）：
  1. 客户业务评审人确认主场景有价值；
  2. 客户技术负责人确认部署、备份、升级边界；
  3. 至少 1 名真实种子用户完成试用；
  4. 客户愿意支付正式上线费用或签署明确采购意向；
  5. PoC 期间的定制需求已从标准能力中分离并单独估算。
正式上线包 → 专业版/企业版授权（版次能力边界见 edition-boundary.md；
  集群/信创等路线图能力在任何版次均不随本次 PoC 解锁）。
```

> `accepted` 只代表**该客户、该环境、该范围**的 PoC 通过，不解锁集群、HA、信创、SLA 或行业效果承诺。
