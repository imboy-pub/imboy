# imboy 端到端加密（E2EE）安全摘要

> 面向：企业 IT 决策者 / 安全审计方
> 版本：2026-07 | 产品等级：Preview（私有化部署）

---

## 一句话定位

imboy 是**服务端零密码学**的企业私有化即时通讯平台——服务器全程不接触明文消息和私钥，即使服务器被完全攻破，攻击者也无法解密任何历史消息。

---

## 核心安全属性

| 属性 | 含义 | 对标 |
|------|------|------|
| 端到端加密 | 消息在发送方设备加密、接收方设备解密，服务端仅转发密文 | Signal / Matrix |
| 前向保密 (PFS) | 长期密钥泄露不影响历史消息安全（Double Ratchet） | Signal Protocol §3 |
| 攻破后愈合 (PCS) | 会话被攻破后，下一次 DH 交换即自动愈合 | Signal Protocol §4 |
| 降级防护 | 高水位标记 (HWM) 阻止中间人强制回退到弱协议 | — |
| 篡改可检测 | SHA-256 哈希链审计日志，任何历史修改即刻暴露 | Certificate Transparency 思路 |
| 身份认证 | Ed25519 签名 + TOFU 固定 + 安全码（60 位指纹）比对 | Signal Fingerprint v2 |

---

## 服务端零知识保证（7 条不变量）

1. 不存储明文私钥——私钥从未离开用户设备
2. 不解密消息——密文作为不透明字节流路由
3. OTK 原子消费——一次性预密钥 FIFO + 行锁，防重放
4. CI 密码学门禁——任何服务端解密代码引入即刻构建失败
5. 推送不泄密——离线推送仅含"发来一条消息"，密文不入推送通道
6. 错误不泄密——API 错误返回不透明 `internal_error`，数据库 schema 不外露
7. 群消息透传——C2G 加密字段全链路 byte-for-byte 不修改

## 与主流企业 IM 对比

| 能力 | imboy | 钉钉/飞书/企微 | Matrix (Element) |
|------|-------|--------------|-----------------|
| 真 E2EE（服务端零知识） | 是 | 否（TLS 传输加密，服务端可读） | 是 |
| 私有化部署 | 是（Docker Compose / Helm） | 部分（需商务定制） | 是 |
| PFS + PCS | 是（Double Ratchet） | 不适用 | 是 |
| 降级防护 | 是（HWM + fail-closed） | 不适用 | 部分 |
| 合规密钥托管 | 是（compliance 模式双密钥） | 服务端全权 | 否 |
| 一键安全审计 | 是（509 tests 可复现） | 不公开 | 需自行搭建 |

## 部署形态

- **Docker Compose**（单机 / 小规模 PoC）：`cd deploy && docker compose up -d`
- **Helm Chart**（Kubernetes 生产集群）：含 Prometheus + Grafana + Loki 可观测性栈
- 数据主权：全部数据（PostgreSQL + Garage S3 附件）留在客户机房
