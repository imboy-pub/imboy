## 3. 社区版 vs 商业版：功能边界设计

**原则**：社区版保留"能用"的核心（引流），商业版靠"好用+合规+规模化"差异化（付费）。

| 能力 | 社区版（免费） | 专业版 | 企业版 |
|---|---|---|---|
| 单聊/群聊/朋友圈/E2EE | ✅ | ✅ | ✅ |
| 单机部署 | ✅ | ✅ | ✅ |
| 钱包/支付基础 API | ✅（已实现） | ✅ | ✅ |
| **集群部署（水平扩展）** | ❌ | ✅ | ✅ |
| **白标/换肤系统** | ❌ | ✅ | ✅ |
| **付费频道运营后台** | ❌ | ✅ | ✅ |
| **加密对象存储增强** | ❌ | ✅ | ✅ |
| **信创国产化适配** | ❌ | ❌ | ✅ |
| **SSO / 审计合规** | ❌ | ❌ | ✅ |
| **优先 SLA / 快速修复** | ❌ | ✅ | ✅（更强） |

> **关键**：集群部署、白标、信创适配必须做成**闭源商业模块**（不进开源仓），否则专业版无付费理由。参考野火：社区版开源单机，专业版闭源集群。

## 4. 信创/国产化策略（2025 政企硬门槛）

政企/国企/金融选型时，信创适配是**硬性门槛**，非加分项。

**imboy 信创适配清单**（专业版→企业版核心卖点）：
- 数据库：PostgreSQL（已用）→ 补适配达梦、金仓、神通
- CPU：x86（已有）→ 鲲鹏（ARM）、飞腾、龙芯
- 操作系统：Linux（已有）→ UOS、麒麟
- 加密：现有 AES → 补国密 SM2/SM3/SM4
- 认证：走信创工委会/厂商兼容性认证（有成本，¥数万–数十万）

> imboy 用 PostgreSQL 18 + Erlang/OTP（非 Java），国产化适配难度**低于** Java 系（野火也是这定位）。Erlang 在通信领域国产化接受度高（华为等大量用 Erlang）。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 集群部署工程量大 | 专业版延期 | 优先单机版+白标先卖，集群作为升级钩子 |
| 信创认证成本高 | 企业版门槛 | 先做技术适配，认证按需（有客户付费再做） |
| 无销售团队 | 获客难 | 创始人直销起步 + 内容营销引流 |
| 宽松许可被白嫖 | 专业版被绕过 | 商业模块闭源（集群/白标/信创），核心差异化不在开源仓 |
| to B 决策周期长 | 现金流慢 | 用定制服务（路径 D）填早期现金流 |

## 关键结论

路径 A 是 imboy 当前最匹配资产的变现通道。**90 天目标不是赚钱，是建成"可售包 + 标杆案例"**；6 个月见首批现金流（¥12–25 万）；12 个月锚定 ¥40–80 万。前提是补齐三个工程缺口（白标/集群/信创）+ 跑通一个标杆案例。许可证（MulanPSL）决定必须靠**闭源商业模块**差异化，不能靠 license 杠杆。
