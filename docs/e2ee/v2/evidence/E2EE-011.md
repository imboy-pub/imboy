## 旧 fail-open（测试复现）
`_unwrapEntry` 旧逻辑：olm 认证失败拒绝（已硬化），但「olm 缺 sid / type 非 int / senderUid 空 / Olm 会话不可用 / 无 olm」→ 一律回退 RSA。恶意服务端删除/改写 olm 字段即可诱导降级。

## 修复后状态机（E2EE-011）
- **v3（olmRequired，meta_version>=3）**：只解 Olm，**任何失败即拒绝返回 null，绝不 RSA**：
  - 无 olm 子对象（删除 olm 攻击 / 无 Olm 身份设备）→ 拒绝；
  - olm 缺 sid / 字段不全（伪造结构）→ 拒绝；
  - Olm 认证失败（伪造 sid）→ 拒绝；
  - Olm 会话不可用（普通异常）→ 拒绝。
- **明确 legacy（meta_version 缺失/<3）**：RSA decrypt-only 读历史密文（认证失败仍拒绝，不降级）。
