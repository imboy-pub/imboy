## 与合同的偏差与决策记录

1. **拒绝层自身的 attempt 同事务落 released**（E-6 实证后修正）：合同 E.4
   伪代码只补偿 done 层，拒绝层残留 reserved 行——同号重试会假命中
   `already_admitted` 而 budget 实际未预占（正确性洞）。实现多清理一步，
   e6 断言三层 attempt 均 released。
2. **重复 admit 的幂等形状**：attempt_id 命中且 state='reserved' ⇒
   `{ok, already_admitted}`（不重复预占，E.7）；命中终结态 ⇒
   `{error, {attempt_state_conflict, Layer}}`（E.4 伪代码的 not-in-reserved
   分支）。伪代码对 reserved-命中未定义返回值，此处按 E.7 表格收敛。
3. **周期粒度固定日**（'YYYY-MM-DD' UTC）：180 允许日/月两种；准入固定日
   粒度，`budget_current_period/0` 导出供管理面播种对齐；粒度不配 ⇒
   条件 UPDATE 0 行 ⇒ fail-closed（H.3 语义自然延伸）。
4. **release/to_uncertain 带 OrgId 前参（/2 而非合同步骤的 /1）**：铁律 6
   租户首参贯穿；数据面 SQL 同时带 organization_id 守卫（attempt 主键虽
   全局唯一，租户守卫使越权误用 fail-closed）。
5. **结算/迁移的 CAS 读法**：FOR UPDATE 行锁下读 state+version，再以
   `WHERE attempt_id AND state AND version` CAS（合同 §4 双条件逐字）；
   并发重复结算被行锁串行化后第二者命中 0 行 ⇒ skipped（I8）。
6. **reconcile 的 provider 查询形状**：`budget_reconcile/1` 接受注入
   LookupFun（测试/未来计量集成面）；`budget_reconcile/0` 默认 unknown ⇒
   released（保守收口）。查询在事务外、逐条短事务写（E.6 冻结）。
7. **实现载体**：数据面（含状态机）在 cs_pg_ai，用例薄封装在 cs_ai_app
   （admit/2、settle/3、release/2、to_uncertain/2、reconcile/0）；
   billing_meter 未触碰（禁止项遵守）。

## 实现注记

- 计数敏感语句（条件 UPDATE / INSERT ON CONFLICT）走 `elib_pg:execute/3`
  —— `elib_pg:query/3` 对非 SELECT 收敛 {ok, []} 会吞影响行数（E.4 的
  "0 行 ⇒ 拒绝"依赖计数）。
- 预算行不存在 / limit NULL（H.3）⇒ 准入谓词 0 行 ⇒ 拒绝（fail-closed）；
  预算行由管理面播种（合同 §7 前置数据同构），AI 运行时不自动建行。
- e5 的 23514 断言用错误文本包含匹配（with_tx 对 CHECK 违规的收敛形状
  跨 {rollback, _}/{error, _} 两可），数值断言（budget 不变）是主判据。
