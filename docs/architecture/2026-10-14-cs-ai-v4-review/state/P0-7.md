## 与合同的偏差与决策记录

1. **F-5 的隐藏前提——WHERE 读列需要 SELECT**：`UPDATE ... WHERE
   organization_id=... AND seq=...` 的 WHERE 读列要求 SELECT 特权，
   aclchk 先于触发器执行 ⇒ 只授 UPDATE 时报 42501（permission denied
   for table），永远到不了 L2 触发器。合同 F3b 探针的"有 UPDATE 权限时
   ⇒ 23514"隐含 SELECT 同时可用；测试按该前提授 SELECT+UPDATE（负例
   语义不变：L2 层拦截的是 UPDATE 本身）。has_table_privilege(UPDATE)
   为 true 而 UPDATE 被拒的悖论由服务端语句日志（log_statement+
   log_line_prefix 取证后已 ALTER SYSTEM RESET 还原）定位闭环。
2. **cs_ai_purge 角色口令**：迁移 180 建角色无口令；套件 setup 内
   `ALTER ROLE ... PASSWORD`（仅本地探针库；生产凭据走 IMBOY_*/环境）。
   新增 probe 角色 `cs_ai_probe_ops`（含 cs_ai_purge MEMBERSHIP）供
   F-3b 的 SET ROLE 伪造尝试。
3. **worker 连接参数**：新 imboy env 键 `cs_ai_purge`（host/port/username/
   password/database/ssl/timeout/codecs）。**codecs 必须与主库配置一致**
   （epgsql_codec_rfc3339_bin）——缺省时 timestamptz 参数落到默认 datetime
   codec，连接进程直接崩溃（真红实证）。
4. **审计事件 id**：elib_tsid:generate/0（注意：elib_tsid 无 next/0）；
   与迁移 180 的 p_event_id 入参契约一致。
5. **worker ts() 直通 binary**：rfc3339 二进制原样传给驱动；integer（epoch
   秒）与 calendar 元组分支保留。
6. **进入条件（K1b）满足**：worker 以 cs_ai_purge（NOSUPERUSER，迁移 180
   创建，仅函数 EXECUTE）独立连接；与 imboy_user 完全分离。
