## 事故记录一：erlc 非 ASCII 二进制字面量静默截断（本机实证，重大）

**现象**：`<<"退款政策">>` 经 erlc 编译为码点低字节截断（退→0x00），进 PG 报
22021/08P01。plain `erlc`（OTP 29, homebrew, 无 ERL_* 环境变量）复现；同文件
`unicode:characters_to_binary/1` 动态构造正确。

**根因**：无 `/utf8` 声明的二进制字符串段对 >255 码点**静默 band 255 截断**
（无编译错误无警告）。本仓惯例本就是全部 `/utf8`，本次新增/未落盘文件漏写。

**修复**：11 个 AI 文件机械补 `/utf8`（55 行；含跨行二进制字面量的二次扫描）。
多行 `<<\n "seg"\n>>` 写法是首轮修复的盲区（`<<"` 同行邻接假设不成立），
beam 字节级核验（0x00 截断序列存在性）驱动定位。

**连带发现（假绿陷阱）**：`cs_ai_intent.erl` 关键词表与 `cs_ai_intent_tests.erl`
测试文本**同时被截断** → 双方一致所以测试恒绿，但生产真实 UTF-8 访客文本永远
匹配不上（转人工关键词全数失效）。修复后两侧字节均正确，测试仍绿。
`cs_ai_prompt.erl`（LLM 提示词）与 `cs_pg_ai.erl:164`（`智能客服` 默认身份名，
截断含 0x00 必触发 22021）同批修复。

**范围外发现（已闭环 2026-10-15）**：`src/api/group_schedule_handler.erl` /
`group_vote_handler.erl` 错误消息、`test/ds/friend_ds_tests.erl`、
`test/logic/group_file_logic_object_key_tests.erl` 等存量文件存在同款裸字面量。
其中两个 API handler 是**在线用户可见的错误消息乱码**路径。→ 已由 b9b900ab
（/utf8 全仓扫尾，4 文件全在）修复；2026-10-15 复扫（erlc 拼接语义探针实证 +
窄口径 binary 字面量扫描）确认全仓仅剩 1 处真暴露
（test/lib/elib_multipart_tests.erl，断言与该字面量无关、无假绿），
e9c7cb21 修复。**全仓 /utf8 暴露清零**；详见 state/POST-MERGE.md。

## 与合同的偏差与决策记录

1. **fetch_gate_config 窄读取（新增 cs_pg_ai 函数）**：gate_1/gate_3 只消费
   v4 列（auto_reply_mode/faq_require_hit），而 v1 `fetch_config` 尚未对齐
  （42703 实证，其字段对齐属 P0-8 对照表）。P0-5 允许修改清单含 cs_pg_ai，
   故 gate 走独立窄读取；P0-8 对齐后可由对齐版 fetch_config 取代。
   cs_ai_port.erl 不在 P0-5 清单，故不加 callback——经 impl/1 动态分发，
   contracts() 冻结面不动。
2. **stale_citation 返回语义**：初版把 gate_4 失效引用映射为 superseded；
   02-B.4 冻结表明确为 `{skipped, stale_citation}`（I10），job 侧按 180 七态
   映射 cancelled + last_error_code='stale_citation'。已按合同修正（真红→绿）。
3. **mark_job_skipped 扩为四因**：expired→dead / superseded→cancelled /
   stale_citation→cancelled / no_grounding→failed（B.4 冻结语义 × 180 CHECK
   值域；细分写 last_error_code）。
4. **gate_7 前置快检（deliver_preflight 内 session_open）**：closed 会话若不
   前置拦截，会在 append 侧以 `session_already_closed` 报错（sender_shape
   先于 AI 钩子），违背 B.4 {skipped, superseded} 冻结形状。前置快检在
   cs_ai_app（P0-5 清单内）解决；事务内 gate_7 复核保留（竞态窗口）。
   cs_session_app 一行未动（不在 P0-5 清单）。
5. **检索 SQL 对 02-D.5 逐字形状的两处类型/方言修正**（语义不变，D-4 验收优先）：
   - `$2 = 0` 使 PG 将 workspace TSID 推断为 int4 → epgsql 编码溢出
     （integer_overflow/int4 → 连接进程死亡 → {db, dead_connection}）。
     显式 `$2::bigint`（同文件 470/497/525/530/535/541 行同款隐患一并修复）。
   - jiebacfg 把词间空格产出 ' ' 词位，`array_to_string(..., ' | ')` 得到
     " | 发票 | 退款" 非法 tsquery（服务端 syntax error 实证）。改为
     string_agg + btrim 过滤空白词位，OR 组语义与合同一致。
     **注**：02-D.5 原文 SQL 在本 pg_jieba 构建上 D-4 必然失败，属合同 SQL
     与实际扩展行为的张力，已记录；02-D.5 原文不回改（评审真源）。
6. **citations_current SQL 重写**：`(f.version,f.id) IN (SELECT unnest...)`
   形状对未使用参数 $3 触发 42P18 indeterminate_datatype；改为多元组
   unnest JOIN（`unnest($2::bigint[], $3::integer[]) AS c(fid,fver)`），
   断言语义不变（count = 引用数）。
7. **dialyze**：cs_ai_app 的 v3 respond 管道存量警告（no local return /
   never called 类）随未跟踪文件落盘进入基线；非 undef 类，lefthook 门
   （只拦 missing/unexported）不受影响；CI ratchet 由 P0-11 处理。
   arch-check：25 处违规全部为既有"裸调用"登记缺口类（8 个 AI 模块未登记，
   P0-9 generate_product_features.py 收口），无新违规类。
