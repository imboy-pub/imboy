## 集成后修复（2026-10-11，main 分支）

**W4-03/04 快照回填根因闭合**——提交 `dc99ce55`：

- **根因**：三处 `ets:match` 匹配模式被误写成带转义引号的单一原子字面量（如
  `'{{rindex, \'$1\'}, \'_\'}'`）。Erlang 语法上这是合法的原子字面量（引号内 `\'`
  为转义引号），erlfmt 与编译器均不报警；但 `ets:match` 把它当作绑定项——与
  ETS 的 `{Key, Value}` 二元组行永不匹配，**恒返回空列表**：
  1. `send_snapshot` 枚举 rindex 恒空 → 恢复节点收不到任何快照事件、仅凭
     snapshot_done 标记即 READY → 上一轮"ready 但 meta 无数据"的全部症状；
  2. `bump_all_fenced` 枚举 fenced generation 恒空 → 整库 flush 不推进代次（潜伏缺陷）；
  3. driver `rindex_dump` 诊断恒空 → 上一轮取证拿不到 rindex 数据（"beam 未重编"
     的误判实源于此）。
- **修复**：三处改为真实元组模式（`{{rindex, '$1'}, '_'}` / `{{gen, '$1'}, '_'}`）；
  本地 ETS 对照实证：修复后返回条目、原写法返回 `[]`。
- **验证**：driver 快照场景重新纳入通过集；三节点 **11 场景连续 3 轮全绿**
  （4631ms/10610ms/4800ms，退出码 0）。driver 编译产物（ebin 内 beam）不入 git。
