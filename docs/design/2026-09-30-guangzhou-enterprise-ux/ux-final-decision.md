# 广州企业 IM：简洁 UI / UX 定稿

## 2026-10-02 最新用户定稿（优先于下方历史版本）

- 个人固定四栏「消息、通讯录、频道、我」；企业固定四栏「消息、通讯录、工作台、我」，无 OA 也不隐藏工作台。
- 个人页面不设顶部「个人」空间下拉；从「我 → 切换企业」进入企业选择器。企业页面保留企业与工作区切换入口。
- 个人通讯录不展示企业卡片、「加入企业」或「创建企业」；加入与创建集中到「我 → 切换企业」。面向用户的「创建组织」文案改为「创建企业」。
- 本期原生验收使用真实 macOS App 替代不可用的 iOS 真机；无客户 OA 时提供固定官网 https://imboy.pub/ 作为展示入口，不把官网当作真实 OA 联调证据。
- 本地实现与验收见 [本期最终记录](./evidence/phase-local-final-2026-10-02/README.md)；个人通讯录入口调整已提交 App `8106bad99a397ac6bd7bf0bb0462933daca46070`。真实客户 OA 联调仍待验证。

English summary: Personal and enterprise scopes both have four tabs. Personal contacts contain no enterprise actions; join/create live under Me → Switch Enterprise. Use native macOS and the official website for this phase; customer OA remains unverified.

下方保留 2026-10-01 历史设计建议及源码采样，供追溯；其中三栏导航、个人顶部空间选择器及无 OA 隐藏工作台的旧决定已被上述用户定稿替代，不是当前实施目标。

日期：2026-10-01。状态：设计定稿建议，可作为实施基线；不代表三端功能已验收。详细交互沿用 [UX V2](./ux-decision-v2.md)，本页明确优先级和取舍。

## 一、统一导航

| 使用场景 | 主导航 | 首次进入 |
|---|---|---|
| 个人 | 消息、通讯录、我 | 个人消息 |
| 企业，有可用 OA | 消息、通讯录、工作台、我 | 企业消息 |
| 企业，无 OA 或当前平台不支持 | 消息、通讯录、我 | 企业消息 |

员工和老板使用同一首页。老板的管理能力放在「我 → 管理企业」，不增加管理首页，不展示统计卡片。复用现有颜色、字号、间距、列表和聊天组件。

## 二、个人与企业切换

左上「个人 ▾ / 企业名称 ▾」为统一入口；手机底部面板、桌面菜单，内容一致。

```text
切换空间
○ 个人
● 示例企业 A
    ● 总部
    ○ 销售协作
○ 示例企业 B
──────────────
扫码 / 输入邀请码加入企业
```

只有一个有效已加入工作区时，选企业直接进入；多个时才显示工作区子项。正常页面显示「企业 A · 总部」，通讯录只显示企业名称。部门是人员组织关系，工作区是群、频道和资料的协作范围，两者不合并。

记住账号自己的最近位置。切换失败停留原页面；无工作区显示明确空态和有权执行的下一步。个人模式保留企业选择偏好；不能用空企业指针冒充个人模式。切账号、退出或失权后重新验证范围，不复用上一身份的列表与 OA 会话。

## 三、员工主要页面

```text
企业 A · 总部 ▾                 搜索  ＋
个人私聊                              ›
[群聊]                         [公告]
─────────────────────────────────────
全员群         周四安排             09:20
销售协作群     新客户资料           08:45
─────────────────────────────────────
工作区资料                            ›
消息          通讯录         工作台      我
```

消息页默认企业群聊，公告分类承载频道；非公告频道显示「频道」标识。个人私聊是跨空间快捷入口，进入个人会话，不把同事之间现有 C2C 改称企业会话。企业应用消息标明来源。

个人消息页保留私聊与个人群；个人频道收进「频道」分类，保留已有订阅能力。企业会话是否排除，依据服务端资源归属判断，不按群名称猜测。通知打开消息时，先验证目标资源权限，再落到对应空间；已经失权时只提示无法访问，不展示缓存内容。

列表只保留头像、名称、摘要、时间和真实未读；置顶、免打扰、草稿沿用既有能力。「＋」仅展示获授权的操作。资料作为次级入口，不新增第五个 Tab。群文件仍从群详情进入；文件保留企业 / 工作区归属，上传人退出不自动删除。

通讯录直接显示「我的部门、组织架构、未分配部门同事」，点部门看到子部门与直属成员；点成员进入资料，提供符合现有权限的「发消息」主动作。目录和 OA 随企业切换，群、频道和资料随工作区切换。

```text
手机通讯录                   桌面通讯录
企业 A ▾  搜索同事 / 部门     部门树        成员列表 / 成员资料
我的部门                     总公司        姓名、所属部门
组织架构                       销售部      发消息
  ▾ 销售部                     行政部
      ▸ 广州销售组           查看组织图 → 同一部门详情
  ▸ 行政部
未分配部门的同事
```

组织图展示部门父子关系，按需展开，不一次铺满员工。人数按接口的直属有效成员数展示；不虚构职位、汇报线或部门负责人。普通员工只读，有企业治理资格者才出现管理按钮。

统一交互规则：手机点部门进入子部门与直属成员，返回保留展开位置；桌面点树节点更新右侧列表。组织图节点进入同一个部门详情。搜索沿用现有昵称、账号和部门名范围，至少输入两个字符；多部门成员在资料中列出全部归属。「发消息」复用现有个人聊天权限，不能绕过好友或聊天限制。

工作台只有一个授权 OA 时直接打开；多个时展示简短的应用列表，选择后进入 H5，保留返回应用列表的入口。审批、考勤等由已有 OA 承载，不另造办公宫格。无配置隐藏入口；加载失败显示重试，不能显示成“企业未配置”。切工作区保留同企业 OA；切企业或账号重新确认身份，包括两家企业使用同一域名的情况。

## 四、老板、平台管理与客服

| 使用者 | 入口与布局 |
|---|---|
| 企业老板 / 企业管理员 | 我 → 管理企业：成员与部门、群与公告、工作区、企业设置 |
| 工作区负责人 | 我 → 管理工作区，仅自己的授权范围 |
| 平台运营人员 | imboyadmin：选定企业后按成员与部门、群与频道、工作区、应用与集成、设置与审计分组 |
| 客服坐席 | 独立 Seat 工作台：左会话与排队、中对话、右客户资料 |

成员详情放邀请、调整、离岗与交接。移交、归档、解散和退出放对象详情末尾，清楚展示影响；失败保留页面与输入。企业 Owner、工作区 Owner、平台管理员、客服坐席保持独立权限，不因合并入口而合并身份。

## 六、实施前必须解决的三点

1. 当前 Workspace 壳直接复用全局 ConversationPage，ConversationModel 没有显式企业 / 工作区归属字段。企业列表要依据授权群资源关联会话；不能只按名称过滤或换标题。
2. 当前已具备按企业发现 OA 条目、账号 / 企业绑定与多应用选择。设计沿用这条链路；跨企业同域 Cookie、服务端退出及真实 H5 身份仍需验证，不能用前端页面重建代替退出证明。
3. App、平台 Admin 与 Seat 的认证面不同；复用页面和数据结构时保留原接口授权，不让老板通过布局取得平台权限。

实施顺序：先统一上下文与数据范围 → 员工导航与通讯录 → 老板治理与独立客服入口 → 验证后删除旧展示。验收覆盖个人 / 企业 A / 企业 B、单 / 多 / 无工作区、切换失败、退出失权、组织树分页、角色越权、OA 身份和真机操作。

## 八、操作路径定稿

| 用户要完成的事 | 入口与动作 | 设计验收目标 |
|---|---|---|
| 回到私人聊天 | 顶部空间名称 → 个人 | 从主页面两次点击，保留个人列表位置 |
| 切到另一家公司 | 顶部空间名称 → 企业；多个工作区才选子项 | 单工作区两次点击；切换成功前保留原上下文 |
| 同企业切工作区 | 顶部空间名称 → 工作区子项 | 群 / 频道 / 资料一起切换；企业目录和 OA 保持不变 |
| 找同事 | 通讯录 → 搜索或部门 → 成员 | 无需先打开企业详情；成员页给出明确发消息动作 |
| 看组织架构 | 通讯录 → 组织架构；宽屏可切组织图 | 树和图共用部门详情；按需展开和分页 |
| 打开办公系统 | 工作台 → 单 OA 直达 / 多 OA 选择 | 不重复建设审批、考勤和报销入口 |
| 查看企业文件 | 消息 → 工作区资料；群详情 → 群文件 | 所属企业 / 工作区明确，失权后不能打开旧缓存 |
| 老板邀请员工 | 我 → 管理企业 → 成员与部门 → 邀请 | 不经过平台后台，不输入内部 ID |
| 员工退出企业 | 我 → 当前企业信息 → 退出企业 | 展示失去的访问范围；Owner 先移交，失败保留原状态 |
| 处理员工离岗 | 管理企业 → 成员详情 → 离岗与交接 | 说明资料保留归属、经办交接和访问撤销 |
| 坐席处理客户 | 授权客服入口 → 独立 Seat 工作台 | 会话 / 排队、对话、客户资料三栏；不挤入员工导航 |

数字是目标操作路径，不是已验证的真机结果。搜索结果可直接进入成员资料；大字号、暗色、加载、空态、失败和权限不足均属于页面必需状态。

最终信息架构：一个空间切换入口、三 / 四个主导航、四类企业管理任务、独立客服工作台。优先复用现有页面与授权接口，先移除重复入口；确认引用和历史兼容后再删除废弃代码。

## 九、细节冻结：让员工和老板按名称办事

以下为目标交互，尚未修改三端业务页面。2026-10-01 复核发现 App 部门管理仍使用成员 UID 和目标父部门 ID 输入框、部门成员行仍以 UID 展示；Admin 企业菜单仍为九项。这些是本轮明确要替换的实际入口。

| 当前操作 | 定稿交互 | 实施边界 |
|---|---|---|
| 输入 UID 给部门加人 | 搜索本企业有效成员 → 勾选 → 确认加入；展示姓名和头像 | 复用目录与成员接口；显示名称缺失先补查询，不能以演示姓名掩盖缺口 |
| 输入父部门 ID 移动部门 | 选择目标部门 → 展示新路径 → 确认 | 自身 / 子孙不可选；服务端版本冲突仍要求刷新确认 |
| 部门成员仅显示 UID | 头像、姓名、多部门归属；点击成员资料 | 仅查询获授权成员，不新增手机、职位或汇报线字段 |
| 加入企业后再找工作区 | 邀请 / 邀请码 → 核对企业名称 → 成功后进入默认工作区 | 重复加入明确显示已加入；失败保留输入；不能编造申请审核状态 |
| 把成员移出部门与离岗混在一起 | 「移出此部门」留在部门详情；「办理离岗」留在企业成员详情 | 移出部门不撤销企业身份；离岗影响单独确认 |
| 管理菜单满屏铺开 | 四类任务列表；具体对象的操作放对象详情 | 停用、离岗、移交、归档各自保留语义，不合并成一个删除按钮 |

范围提示采用用户能看懂的名称：

| 页面 | 顶部名称 | 数据范围 |
|---|---|---|
| 个人消息 / 联系人 | 个人 | 当前账号的个人关系和会话 |
| 企业消息 / 群 / 频道 / 资料 | 企业 A · 总部 | 当前获授权工作区的资源 |
| 企业通讯录 / 组织图 | 企业 A | 本企业目录；多部门身份照实展示 |
| 工作台 | 企业 A · 工作台 | 本企业授权 OA；多个应用才显示选择列表 |
| 企业管理 / 工作区管理 | 管理企业 A / 管理总部 | 对应治理权限；不同资格不互相继承 |

不把 Workspace membership 当作 Organization membership。仅有工作区协作资格的人，可以进入其获授权协作资源；不能因此展示企业通讯录、OA 或企业治理。若广州文件规则要求企业在职身份，资料入口及读取必须遵循该规则，不能承诺所有协作者都能读文件。

### 布局与状态

- 手机：顶部名称与搜索、内容列表、底部三 / 四项导航；选人 / 选部门用独立页面，避免连续堆叠弹层。成员详情底部主动作「发消息」，治理动作放右上更多菜单。
- 宽屏：左主导航、中列表、右详情；通讯录以部门树替换中间列表的分类区。窄屏逐层进入，返回保留筛选、展开位置与滚动位置。复用现有响应式断点和视觉 token，不另外建立广州样式体系。
- 组织图：部门卡片和父子连线；默认只展开第一层，提供展开、收起与回到根节点。手机默认树列表，组织图作为按需入口。员工姓名放部门详情，不把所有人员铺到图上。
- 加载：首次显示列表骨架；刷新保留原内容并标示正在更新。切空间未成功前保持原范围；失权立即停止展示该范围旧内容。空态给出有权执行的一步，错误态提供重试。
- 搜索：随页面限定范围，提示「搜索本企业同事 / 部门」或「搜索当前工作区群」；沿用真实接口能力，不出现无法兑现的全局搜索框。
- 可访问性：动作触达区至少 44 逻辑像素；名称可换行或截断但详情可查看全文；状态同时使用文字；暗色、大字号和键盘焦点均列入验收。

三端职责固定：App 负责员工通信与老板日常治理；Admin 负责平台运营与集成配置；Seat 负责客户接待。OA 的审批、考勤、报销在客户已有 H5 中完成。Internal API 是集成协议，不另造一套员工操作台。

英文摘要 / English summary: One scope switcher; three personal tabs and three or four enterprise tabs. Directory follows the organization; collaboration resources follow the authorized workspace. Replace raw identifier inputs with authorized people and department pickers. Keep platform administration, customer-service seats, and OA responsibilities separate. These are design targets, not verified implementation results.

## 十、2026-10-01 三端复核后的冻结结论

本轮明确敲定上述信息架构，不再增加首页方案。用户看到「个人」「企业名称」「工作区名称」；Organization / Workspace / scope 留在实现与接口文档中。

### 必须兑现的五条产品规则

1. **通信先行**：个人三项「消息、通讯录、我」；企业有授权且平台支持的 OA 时四项「消息、通讯录、工作台、我」，否则三项。员工与老板共享通信首页，老板不额外经过仪表盘。
2. **切换只有一个入口**：顶部名称打开同一个选择器；单工作区选企业即进入，多工作区才选择子项。切换成功后同步页面名称与资源；失败保留原位置。通讯录随企业，群与频道随工作区，个人私聊明确进入个人范围。
3. **组织架构服务找人**：手机默认部门树，点部门进入子部门与直属成员；宽屏左树右成员。组织图是同一目录的可选视图，默认展开第一层，点节点打开同一部门详情；不新增无法兑现的职级或汇报关系。
4. **老板按对象办事**：「我 → 管理企业」固定四项「成员与部门、群与公告、工作区、企业设置」。邀请、调整部门、移交、离岗各在对应对象详情；选人展示姓名和头像，选部门展示名称和路径，不要求用户输入 UID 或部门 ID。
5. **三端职责清楚**：App 承担通信与企业日常治理；Admin 企业区收敛为五个任务组；Seat 保持会话队列、对话、客户资料三栏。OA 办公事项继续由客户 H5 承载。

### 裁剪与实施门槛

广州企业界面先隐藏概览、项目、社交发现和重复工具入口；个人与其他产品配置按原能力保留。旧页面只在新路径可用、引用检查与历史兼容通过后删除。隐藏入口不撤销安全协议或服务端能力。

首批实现依次交付：统一切换与授权范围 → 消息 / 通讯录主导航 → 选人选部门与老板四项治理 → Admin 分组。组织图复用部门数据；若节点和分页还未接入，必须明确标为设计预览。
