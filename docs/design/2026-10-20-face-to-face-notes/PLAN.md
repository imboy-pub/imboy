## 2. 八条并行工作流（上限，不是固定开八个）

| 通道 | 所有权 | 共享文件限制 |
|---|---|---|
| C 主集成/契约 | 计划、台账、契约、迁移编号、路由注册、聚合生成物、最终集成 | 仅主集成者写全局router/i18n生成物/依赖清单等；不得代提交外来WIP |
| B 领域/API | talk_record Handler→Logic→DS→Repo与领域测试 | 同一模块任务串行；向C提交路由新增片段 |
| A 附件/治理 | 既有附件扩展、引用GC、治理与相关测试 | 先与C登记共享修改路径；不改存储SDK、不建独立物理删除链 |
| P 录音处理 | 拼装/持久处理状态、App豆包异步ASR适配与相关测试 | P内任务串行，不能与A同时改附件全局文件；App共享文件与F/R先登记 |
| S 摘要/派生产物 | App智谱摘要适配、结果校验、导出、正常责任移交及测试 | 独立模块；不直接改B模块，需由C集成接口；App共享文件与F先登记 |
| F App数据 | Model/Api/Repository及契约测试 | 不改录音服务或UI组件 |
| R App录音/上传 | 长录音、恢复、补传与服务层测试 | 独占真机录音测试；音频组件共享修改先登记 |
| U App界面 | 入口/列表/详情/分享等UI、widget/视觉用例 | 多UI任务同通道串行，主题/路由只交C集成 |

Q为审查/验收角色，在可用槽位内替换已空闲通道，不是第9个常驻worker。运行worker数≤min(8,宿主可用槽位)；若宿主限制包含主控制器，则预留其槽位。当前会话实际容量不可被计划强行提高。子agent不得再递归扩队；不创建用户可见的新会话替代worker。

并行候选例：T01完成后T02/T03（C为主集成职责，T03只读可行性取证可委托空闲worker；全局契约文件仍由C串行归并）；契约与可行性通过后T04/T08（T08仅组件契约开发）；T04后T05/T06/T09/T10；随后按DAG动态派发。不同lane也可能触及同一文件或设备，路径/资源冲突时仍串行。不要为了凑8路放行未满足依赖的任务。

## 10. 可接管而不可双写 / Fencing and journal

锁不仅是目录：state_version是每次状态写入的递增版本，controller_epoch是控制器接管后递增的栅栏令牌。worker领取任务必须携带epoch、任务attempt、工作树与allowed_paths；旧epoch任务结果可归档但不得直接更新台账、集成候选或覆盖文件。所有worker只写自己隔离工作树，不在共享main修改源码；epoch不能约束已启动进程时，也不会互相覆盖主树。

每次状态变更：在单控制器锁内核对预期state_version/epoch→写持久journal的完整下一状态与old/new hash→flush/fsync→写同目录临时state→fsync→原子rename→按平台支持刷新父目录。原子rename只保证可见性，不等于断电持久性，平台无法保证时保留已fsync日志用于reconcile。用主控制器串行队列，不伪称无锁hash比较就是CAS。每次状态更新保存last-known-good快照；重放以journal版本/epoch及代码事实对账，禁止直接把较新的墙钟时间当权威。

claim超时后核验实际worker/会话/进程，确认退出后递增attempt重新派发；控制器接管epoch必须递增。恢复演练包括：状态落盘前中断、日志已写state未rename、worker完成主控制器中断、控制器接管后旧worker返回、证据文件丢失、设计文件hash漂移。预期都不得重复执行破坏性动作、伪造accepted或丢弃本任务源码。
