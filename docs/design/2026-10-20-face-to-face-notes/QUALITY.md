# 执行计划质量评估 / Plan quality assessment

修订8说明（2026-10-21）：以下评分、全部todo及30项测试是2026-10-20修订7规划阶段的历史快照，不描述当前实施进度。当前已开展实施与验证；完成状态须读取仓外执行台账并核对实际候选证据。修订8另有33项校验器测试通过，覆盖显式外部台账读取且不写入文件；这不证明任务已验收，不重评或继承9.8分作为当前交付质量。真实设备、模型质量及最终集成证据仍须独立验收。

日期：2026-10-20；评估对象：PLAN v7及状态/提示词/校验合同，不是业务实现质量，也不是已上线验收。

## 1. 评分口径

目标约9.9/10。以下为主会话基于静态审查和计划校验的工程判断，不是外部认证，也不把生成测试总数等同质量分。实际恢复、平台与模型可行性有独立准入门槛。未完成的准入项不得靠自评分数放行。

| 维度 | 权重 | 评估依据 |
|---|---|---|
| 范围与边界 | 10% | 首版/未来能力、个人企业归属、授权与非授权操作明确 |
| 依赖与可调度性 | 15% | 25任务DAG；组件就绪与真实accepted分离，防止集成等待循环 |
| 并发与资源所有权 | 10% | 8worker上限、实际容量预留、路径/设备/迁移/生成物互斥 |
| 中断恢复 | 15% | 单控制器、state_version/epoch、持久日志/快照/恢复与旧worker隔离 |
| 测试可执行性 | 10% | 各任务具体产出/失败路径，分步与最终检查入口，真实模型/设备不可用时不假通过 |
| 验收可追踪性 | 15% | A01—A08对应任务，确定性不变量，质量阈值先冻结，角色矩阵与UI定量门槛 |
| 证据与候选绑定 | 10% | 两仓提交或WIP哈希、模型/配置/样本hash、退出码，漂移重验与FAIL/SKIP/ENV保留 |
| 附件生命周期集成 | 5% | 现有上传/确认/引用/GC/留存/hold链，业务不得自建物理删除链 |
| 审查及权限边界 | 5% | 独立审查；不隐含commit/main合并/外部服务/生产授权 |
| 续接提示词与维护 | 5% | 相同提示词读取持久状态，revision与进度版本分开，hash变更需明确评审 |

## 2. 本轮已修正的关键缺陷

1. 前端任务等待真实联调才能accepted，T22又等前端accepted，存在逻辑等待环；新增component_ready与acceptance_dependencies，不把fixture当业务通过。
2. 未授权commit/合并main时原集成步骤含糊；改为独立集成工作树应用已审自有补丁，WIP快照/哈希同样可作为候选。
3. 控制器锁缺失持久版本和接管隔离；明确state_version/epoch/任务attempt、日志与崩溃窗口恢复合同。
4. 状态文件可更改依赖/权限却缺静态报警；增加不可变任务定义、审批来源、容量/资源冲突及最终候选结构校验。
5. 只有“模型质量通过”而未规定怎么定标准；要求T03在最终评测前冻结带样本hash/模型版本的quality-contract和用户确认，不事后降低阈值。
6. 缺需求到验收路径映射；补A01—A08及零越权/零误删/零重复创建等可证伪不变量。

## 3. 当前证据与未完成项

- 计划DAG/状态/manifest有只读校验器；30项正反例覆盖初态、依赖循环/漂移、非法组件状态、越权启动、旧epoch、容量/路径/资源冲突、缺失/旧候选证据、非零退出码假PASS及假COMPLETE。
- 这些不是运行时锁/磁盘断电恢复演练。T01必须真实演练异常中断及接管，记录不重复写、不丢源码、不误接纳旧结果的证据。
- 当前任务全部todo；target_platforms、processor_selection、model_quality_thresholds、retention_and_export_policy尚待确认。T02/T03未满足决策和视觉/设备证据，不能accepted。
- 初态校验通过只证明计划文件内部可检查。未来执行者仍需实际实现调度协议或使用已验证等价工具，不能声称只运行validate_plan.py就具备自动接管系统。

最终分数必须结合独立审查结论与上述准入边界说明；不会为达到9.9而将未执行事项填PASS。本轮不运行业务开发、不提交、不部署。

## 4. 独立审查修正与用户补充

代码审查与Python专项独立只读审查提出：空manifest可通过、验收范围覆盖不足、component_ready缺证据、租约仅非空检查。已修必需文件集合/哈希格式、每任务必跑check清单及命令绑定、组件证据与候选绑定、ISO租约及时效检查，并补正反例。另一个通用计划独立审查未完成，未将其记为通过。

最新用户要求已纳入：单次会话优先、不逐卡询问；模型等依赖阻塞不传播到独立开发；广州收口计划与原RUN_ROOT只读保护；资源隔离/不可证明独占则等待/抢占证据失效，新增A09。当前不对真实设备、数据库或对方进程执行占用探测或故障注入。

独立复核补充：发现测试绑定仍来自可变台账；现冻结副本进入execution-contract.frozen_test_bindings并由manifest固定，校验器拒绝同时改台账与结果但未改冻结契约的情况；操作绑定更新需主控制器锁、独立审查与journal，不能暗改验收范围。新增相应反例，共30项。

主会话对修订后静态计划质量的估计约9.8/10，接近9.9目标，属于工程判断而非测量或独立认证。可调度性、持久恢复与跨会话资源边界已明显收紧；实际执行就绪仍需T01资源/恢复演练、T02视觉与契约冻结、模型/平台可用性验证。未完成的通用独立计划审查未计作通过；不把规划得分转化为业务完成率。
