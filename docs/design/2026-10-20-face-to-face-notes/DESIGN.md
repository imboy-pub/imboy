# 面聊记录 / In-person Notes — 设计提案 v4

日期：2026-10-20。状态：**待用户确认 / DESIGN PROPOSAL ONLY**。
本目录只有设计原型和技术契约草案；不代表录音、ASR、声纹、AI 摘要或分享能力已实现，不修改生产 API、数据库或业务代码。当前任务不提交。

## 1. 产品定位与推荐决策 / Product decisions

入口短名「面聊记录」，说明「记录面对面聊天，整理讨论与待办」。企业工作台新增一个分组列表入口；个人空间工具入口也可进入，同一交互体系。避免把完整宣传语用作导航标题。

**推荐 V1：录音、会后转写、区分说话人、人工校对、回听、摘要草稿、受控分享。** 自动识别同事真实姓名需要另行注册声纹和模型支持，作为可选后续能力；不阻塞录音。实时字幕是独立增量，V1 录音中显示真实录音状态和手动重点，不伪造已转写文本。AI 未配置时可保存、回听和手动记笔记；ASR 未配置时明确「仅录音」，不显示假摘要。

待本次确认的范围：是否接受 V1 不强制注册声纹、默认仅创建者可见、企业内显式分享、会后转写与 AI 草稿；若必须首版实名声纹识别，需要追加供应商/自托管模型及质量验证，再进入实施。

## 3. 信息架构 / Information architecture

工作台（企业）或工具（个人） → 面聊记录列表 → 新建准备 → 录音中 → 保存/处理 → 记录详情。
详情 → 原文定位回听 / 修改标题与文字 / 发言人校对 / 分享权限 / 导出 / 删除。
声音档案仅保留独立概念页供评审，移出首版准备页与默认导航。

| 页面 | 主要内容 | 主操作 | 次操作与返回 |
|---|---|---|---|
| 列表 | 当前空间、搜索、记录标题/时长/状态/可见范围 | 新建记录 | 全部/我创建/共享给我；空态同一入口 |
| 准备 | 标题可空、归属开始前可选、语言、处理方式、可见范围 | 开始录音 | 确认已告知现场人员；麦克风拒绝时说明并可重试/去设置 |
| 录音中 | 大计时、真实输入电平、重点时间点、本机保存状态 | 暂停/继续、结束 | 返回收起到持久录音条；不自动结束，不允许同时启动第二条 |
| 保存 | 本机文件状态、上传进度、转写排队/处理中/失败 | 查看记录 | 网络恢复重试、稍后处理；本机草稿不因上传失败消失 |
| 详情 | 摘要/原文页签、固定迷你播放器、讨论重点/待办草稿 | 回听、校对 | 分享、导出、删除；摘要无权限/未配置时真实降级 |
| 发言人 | 说话人 1/2、试听片段、标记来源 | 设置显示名或认领自己 | 编辑者可标记同事但标注「人工标记」，不等于本人认证 |
| 分享 | 当前可见范围、明确接收者及权限 | 保存授权并分享卡片 | 撤销即时阻止新访问；转发卡片不扩大原权限 |
| 我的声音 | 可选用途、采样质量、明确同意、删除 | 开始采样/删除档案 | 后续能力；跳过仍可录音，不能代替他人同意 |

## 4. 视觉与交互规范 / Visual and interaction system

复用 `imboyapp/DESIGN.md`，不新增另一套产品品牌：AppColors.primary #2474E5；AppSpacing 4/8/12/16/20/24/32/48；FontSizeType 对接实现时的既有字号语义。网页 prototype 的 CSS/JSON 是这些 Token 的设计映射，不导入业务。

- 白/分组灰背景，主操作品牌蓝；录音中红点配文字，颜色不独立承载状态。无渐变、无大插画、无多层重阴影。
- 统一左右 16pt，图标列 24pt，列表头像/图标 40pt，文字与尾部时间各自对齐；记录列表无需每行箭头。
- 标题 22/20pt、正文 16pt、辅助 14pt、计时 40pt；辅助文字使用高对比语义色。文本可换行，不以固定高度裁切。
- 触达区至少 44pt，主按钮至少 48pt。页面内容滚动，底部操作区占据真实布局并附安全区，不覆盖最后一行；软键盘弹出时同样遵守。
- 手机单列；宽屏最大 1120px，列表/详情可双栏（本稿用独立页面切换展示）；窄屏 320px、大字体、深色都保持内容可达。
- 整理状态与音频可播放状态分离：有录音但转写失败，仍可播放/重试。模型未配置、无权限与空内容各用不同文案。
- 全文搜索点结果跳原文时间点；播放时不强制抢走用户正在看的位置，显示「回到播放位置」。
- 摘要与待办标注「AI 草稿，待确认」，每条关联原文片段；首版只确认草稿，不创建正式任务；未来任务联动、邀请和通知均需另外设计和明确操作。

## 5. 关键状态与边界 / State and recovery

1. 录音使用本地分段、加密临时存储与段清单；网络断开继续本机录音。锁屏/后台能力以平台真机验证为准，不能仅凭 UI 声称支持。
2. 来电/系统抢占麦克风→真实暂停，持久显示中断原因；恢复必须用户点击。不在暂停时继续计算有效录音时长。
3. App 异常退出→下次恢复已落盘分段，明确实际保留时长。低电量/空间不足提示可保存，磁盘写入失败立即中止并告知，不显示保存成功。
4. 结束前确认「结束并保存」；不足内容仍保存录音、说明无可转写语音。删除本机草稿需二次确认。
5. 采集阶段不支持变更这条记录的归属；用户仍可浏览其他空间，跨空间保留标注原归属的录音条，点开回原记录。原型顶部场景切换是评审控件，其录音中限制不代表产品要禁用全局空间切换。企业离职/撤权立即停止新的上传和读取，保留本机待处理告知，不能转存到个人空间绕过权限。
6. 编辑采用 revision 乐观锁；冲突保留本地输入，供对比/重新提交。人工改名不被模型重跑覆盖。
7. 分享默认仅创建者；选择同事不自动共享。企业公开链接、匿名访问、全员默认可见均不在 V1。
8. 权限拒绝/处理失败/录音中断/离线/空态均有明确操作。本原型所有录音和转写内容均为模拟，不请求麦克风、不上传、不调用模型。

## 6. 数据处理设计 / Data handling

创建者确认已告知现场参与者是流程记录，**不是平台验证每位现场人员实际同意的证明**。界面展示用途与处理方式；记录用于转写/摘要时需向选定处理器提供音频或文本，不能标为聊天 E2EE。优先部署内处理；外部服务在实例配置、用途和数据流明确后另行接入，不默认发送。

持久声音档案仅本人自愿创建，可撤销/删除；不从普通聊天语音偷偷训练，不做全库实名检索。临时说话人聚类只用于本次记录，不等于个人声纹。原始采样通过质量校验后清除，保留期限/异步清除状态有审计；模型 embedding 加密存储，业务接口不返回向量。归属企业不代表企业管理员可任意浏览所有面聊。

推荐记录保存期限由部署策略给出并在保存前展示；设计暂不硬编码 30/90 天。删除先撤销访问并进入 cleanup pending；附件沿统一生命周期释放引用、检查留存/hold与其他引用后处理，界面分别显示已删除记录、受留存保护、清理失败或清理完成；不自行删除音频。备份按实例既有到期策略清除，不承诺即时从备份消失。注销预检展示未完成录音/待清除任务，复用现有账户生命周期入口。

## 7. 实施前证据与缺口 / Existing evidence and gaps

静态查看：App 已有 flutter_sound、audio_session、just_audio 依赖，`lib/component/voice_record/voice_widget.dart` 为聊天语音交互；附件已有受控上传/授权读取。它们不等于长录音分段、后台恢复、ASR 或声纹能力已经存在。

本次 src 范围关键词检索未找到明确 ASR/diarization/voiceprint 实现；不能据此保证仓库绝无相关代码。设计新增面聊独立业务域，复用附件基础设施，需新增面聊 ACL purpose adapter，避免通用附件 ID 绕过记录权限。后端保持 Handler→Logic→DS→Repo；异步转写用持久任务/lease，不在 HTTP 请求里等待模型。

实施前需定向核对长录音设备能力、附件时长/大小限制与上下文授权、异步任务执行设施、模型/成本/语言支持、组织及工作区权限服务。不得直接复用聊天短语音大小限制充当面聊上限。建议初始上限 2 小时/条、并发 1 条本机录音，最终由实例 capabilities 返回，不能在 API 客户端硬编码。

## 9. V2：个人与企业 UI / Personal and organization journeys

业务命名统一 `talk_record`，API `/api/v1/talk-records`；原设计目录名保留以免已分享链接失效。

同一功能、两种归属，视觉组件保持一致，流程内容按上下文变化：

| 页面 | 个人空间 | 企业空间 |
|---|---|---|
| 固定入口 | 我→个人工具→面聊记录 | 工作台→协作工具→面聊记录 |
| 列表 | 访谈、读书交流、灵感；筛选我创建/共享给我 | 项目例会、评审、拜访；当前企业/工作区，仅列有权记录 |
| 新建 | 可空标题、语言、处理方式、保存到个人空间 | 同样基础项＋可选工作区、从企业目录选择参与同事 |
| 保存位置 | 开始前可选个人或有权企业 | 不默认指定未知工作区；可保存到企业空间而不选工作区 |
| 发言人 | 自定义姓名/匿名说话人，可关联联系人 | 可标记有权企业目录内同事；人工标记不等于本人认证 |
| 分享 | 明确选择联系人 | 明确选择符合企业/工作区权限的同事；导出开关受企业策略限制 |
| 离职/撤权 | 不影响个人记录 | 显示无访问权限，隐藏原文、标题与参与者，不自动转个人 |
| 更多操作 | 编辑、导出、删除 | 同上按能力显示；另有移交管理责任（需二次确认） |

原型顶部「个人场景 / 企业场景」仅供评审，不是产品内新增 Tab。产品实际从当前空间的固定入口进入；准备页「保存到」允许用户在开始前更正归属，切换时清空不适用参与者/共享选择；若已填标题或笔记，需要保留通用内容并告知变更，不静默丢稿。开始后固定，跨空间归属迁移不在首版。

V2 原型补齐两个固定入口、保存位置页、不同准备/分享文案、不同示例列表、企业访问失效页。录音/上传/回听使用同一套交互，不为个人与企业维护两份录音逻辑。首版仍采用会后转写、匿名分人与人工校对；声纹是可选后续能力。

评审用数据均为虚构，联系人/同事不对应真实账号；按钮模拟不会真正授权、通知、移交或录音。原型尚未通过浏览器像素验收；可执行脚本检查不等于设备验收。表结构和 API 已同步 V2，采集过程从主对象分离为 talk_record_capture，支持以后补录/导入扩展，但不将未来来源标为已支持。

V2 定向检查：个人/企业两种上下文各9个页面状态的脚本渲染与事件语法通过，验证个人不显示工作区、分享候选文案区分、录音中禁止切换归属；另有记录管理页。此为无浏览器布局引擎的静态/状态检查，不是视觉或设备验收。

附件生命周期补充：音频及派生产物必须进入统一附件系统；面聊只保存业务引用。删除区分逻辑删除、留存/hold阻塞与物理清除，企业附件列表新增面聊分类仍需实现。具体接入和验收合同见 BACKEND-API.md §10，当前并未实施。


## 10. V3 精细化与收敛 / Review refinements

首版原型移除“我的声音（后续）”导航与准备页入口；概念稿源仍留存，不代表已开放。准备页先展示保存到、处理方式和开始录音，企业工作区/参与者为选填；麦克风系统授权在用户主动开始后触发，不与声音档案同意混为一项。未配置转写时主按钮明确“开始录音”，处理方式“仅录音”，不要求与实际用途不符的AI同意。

页面状态矩阵：准备（可开始/无权限/配额不足/无处理能力）；录音（录制/暂停/中断/本机存储失败/接近上限）；处理（上传/缺段/排队/转写/无语音/部分失败）；详情（仅录音/有原文/有摘要/摘要已过时/只读）；分享（未共享/名单/角色/撤销/策略禁导出/版本冲突）；删除（确认/逻辑删除/留存阻塞/失败/完成）。本原型尚未把矩阵所有状态做成可点页面；进入开发前以 PLAN.md P1 为门槛补齐并验收。

个人首版可保留简单准备，不必先选参与者；企业同样不应强制选同事才开始。详情使用资源能力控制：viewer不出现校对与删除，editor可校对但无分享管理，owner才能授予权限。企业策略阻止导出是某个能力状态，不应把所有企业实例永久禁用导出；原型当前仅演示“禁用”状态，实施必须按实际capabilities。

分享保存后区分“权限已保存”与“卡片已发送”，完整授权名单、角色、到期与撤销入口必须可见（仅owner）；主按钮不把两者混成自动通知。撤权提示说明已导出副本无法收回。删除不能只用“清理队列已提交”替代最终清理状态。

确认原型后对齐视觉组件与主流程；系统权限/分享面板遵循平台行为。施工基准包括页面状态、Token、资源角色、窄屏大字安全区与可访问性；现有prototype仅状态模拟，距离可逐页验收的1:1施工稿还有 P1 工作，不能以脚本渲染通过代替视觉完成。
