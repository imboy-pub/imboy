#### 消息搜索响应体 (`/v1/fts/msg`)

```json
{
  "total": 5,
  "page": 1,
  "size": 20,
  "list": [
    {
      "message_id": 98765432100,
      "msg_type": "text",
```

> The `highlight` field is generated by `ts_headline` and is only present when advanced search options are passed.

### 1.4 pg_jieba 分词模式 / Tokenization

后端使用 **jiebacfg** 配置（pg_jieba 中文分词）：
- 先用 `to_tsquery('jiebacfg', $1)` 解析关键词
- 将连续词 `<->` 关系改写为 `|`（OR 语义），提升召回率
- 增强搜索用 `ts_rank` 计算相关性得分，基础搜索按 `created_at desc` 排序

## 5. 高亮渲染实现状态 / Highlight Rendering Status

**当前行为（实际）**：  
Flutter 使用 `highlight_text` 包，基于用户输入的搜索词在本地进行关键词标红（`_highlightWords` map）。与服务端 `ts_headline` 生成的 HTML 片段无关，未消费 `highlight` 字段。

**后端能力（未被使用）**：  
增强搜索路径（带 Options 时）会通过 `ts_headline('jiebacfg', m.payload, websearch_to_tsquery(...))` 生成带 `<b>` 标签的 HTML 高亮片段，但 Flutter 的 `MessageSearchResult.fromJson` 中没有解析 `highlight` 字段。

**影响**：  
- 简单关键词：前端本地高亮效果尚可  
- 中文分词场景（如搜索"东区开会"分词为"东区 | 开会"）：后端高亮更准确，前端高亮可能不匹配分词结果

## 6. 推荐修复项 / Recommended Fixes

### P0 — 阻断性问题（会话内搜索无效）

**问题**：Flutter 在会话内搜索时传递 `conversation_uk3`（字符串，如 `c2c_111_222`），后端 `fts_handler` 只接受 `conversation_id`（integer）。后端代码无对 `conversation_uk3` 的解析逻辑，导致会话内搜索**退化为全局搜索**。

**修复方案（二选一）**：  
A. **后端增加参数**：在 `parse_search_options/1` 中解析 `conversation_uk3` 字符串，从中提取 peer IDs 并转为 `conversation_id` 或 `from_id`/`to_id` 过滤条件。  
B. **前端解析 uk3**：Flutter 在调用前将 `conversationUk3`（如 `c2c_111_222`）解析出对端 UID，传递 `conversation_id` 或 `from_uid`。

---

### P1 — 字段名不匹配（消息结果解析失败）

**问题**：后端响应字段 `message_id`、`from`、`to`，Flutter 解析时使用 `json['id']`、`json['from_id']`、`json['to_id']`，导致 `id`/`fromId`/`toId` 全部为空字符串。

**修复方案**：  
在 `MessageSearchResult.fromJson` 中兼容两套字段名：

```dart
factory MessageSearchResult.fromJson(Map<String, dynamic> json) {
  return MessageSearchResult(
    id: parseModelString(json['message_id'] ?? json['id']),
    fromId: parseModelString(json['from'] ?? json['from_id']),
    toId: parseModelString(json['to'] ?? json['to_id']),
    // ...
  );
}
```

---

### P1 — 时间参数格式不匹配

**问题**：Flutter 传递 `start_time`/`end_time`（毫秒整数），后端期望 `start_date`/`end_date`（`YYYY-MM-DD` 字符串）。

**修复方案（推荐前端改）**：  
在 `FtsApi.searchMessages` 中将毫秒时间戳转换为 `YYYY-MM-DD` 格式，并改用 `start_date`/`end_date` 参数名：

```dart
if (startTime != null) {
  final dt = DateTime.fromMillisecondsSinceEpoch(startTime);
  queryParams['start_date'] = '${dt.year}-${dt.month.toString().padLeft(2,'0')}-${dt.day.toString().padLeft(2,'0')}';
}
```

---

### P2 — 未消费后端 highlight 字段

**修复方案**：  
在 `MessageSearchResult.fromJson` 中添加 `highlight` 字段：

```dart
final String? highlight;
// fromJson:
highlight: parseModelNullableString(json['highlight']),
```

在 `MessageSearchPage` 优先使用 `result.highlight`（去除 `<b>` 标签后）作为摘要展示，关键词高亮继续使用 `highlight_text`。

---

### P2 — FTS 用户搜索接口未对接

**修复方案**：  
在 `FtsApi` 中添加 `searchUsers` 方法，调用 `/v1/fts/user_search`（参数：`keyword`, `page`, `size`）。搜索页的联系人搜索入口替换为此接口，实现中文分词搜索。

---

### P3 — 消息类型/发送者/排序过滤未传递

`FtsApi.searchMessages` 的 `type` 参数（`all`/`C2C`/`C2G`）在 `type == 'all'` 时不传递，后端默认 `C2C`，导致 `type=all` 时只返回私聊消息。

**修复方案**：`type == 'all'` 时可分别查询 C2C 和 C2G 再合并，或后端新增 `type=all` 支持。
