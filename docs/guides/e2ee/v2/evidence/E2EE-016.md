## 已确认漏洞（修复前）

1. **notes 边界靠启发式猜测**：`_extractCiphertext` 用「尾部 4 字节当长度 + 内容是否可打印 UTF-8/CJK」猜测是否有备注。密文尾部若恰好像「长度+可打印」→ 误判密文/备注边界 → GCM 认证失败或返回错误密文。非确定性。
2. **无大小上限（OOM）**：`importBackup / verifyBackupFile / testPassword` 直接 `readAsBytes()`，`unpackBackupBytes` 对任意大 bytes 无上限 → 恶意/损坏的超大文件可致 OOM。
3. **KDF 迭代数来自文件且无上限（DoS）**：`header['iterations']`（攻击者可控）直接喂 `deriveKey`。写入 `2^32-1` 可让 PBKDF2 挂死。
4. **短文件 RangeError 崩溃**：`_parseFileHeader` 仅校验 `< 32`，但随后按 offset 切 salt/iv/tag 需 ≥76 字节；40 字节文件 → `sublist` RangeError（Error 非 Exception，非确定性拒绝）。
5. **恢复覆盖物理设备 DID**（`e2ee_backup_import_page.dart:505`）：`_applyRestoredKeys` 用备份内 `device_id` 覆盖本机物理 DID → 本机冒充备份来源设备，**破坏 E2EE-013 设备绑定写入授权**。

## 修复

### `lib/service/e2ee_local_backup_service.dart`
- 新增边界常量：`maxBackupBytes=64MiB` / `minBackupBytes=77` / `minKdfIterations=1` / `maxKdfIterations=1_000_000` / `maxNotesBytes=64KiB`。
- **notes 确定性布局**（req1）：`notes_length` 写入 32 字节文件头 reserved 区（offset 22，uint32 大端）；备注内容附于文件末尾。reader 据头部权威长度确定性定位边界，删除 44 行启发式猜测。头部布局 `magic8+ver2+algo2+iter4+saltLen2+ivLen2+tagLen2(22)+notesLen4(26)+reserved6(32)`。
- **上限前置**（req2）：`_ensureSizeBounds(length)` 在 `readAsBytes`（用 `file.length()`）与解密/派生前拒绝超大/过小；`_parseFileHeader` 校验 `iterations∈[1,1_000_000]`；`_extractCiphertext` 校验 `notesLength≤maxNotesBytes` 且密文≥1 字节。所有拒绝走 `ArgumentError`（确定性，不泄漏签名 oracle）。

### `lib/page/settings/e2ee_backup_import_page.dart`
- **req3**：`_applyRestoredKeys` 删除 `setDeviceId(result['device_id'])`；备份 device_id 仅作归档元数据（成功弹窗展示），不覆盖当前物理 DID。恢复仍写 private/public key + keyId（属密钥而非设备身份）。

## 向后兼容
旧格式无备注文件的 reserved 区为 0 → `notes_length=0` → 密文=全部剩余，正常恢复。旧「尾部长度」格式**仅当曾写入备注**才失配，但 `userNotes` 全仓**无生产调用点**（`rg` 确认，仅测试），故无此类文件；且 alpha.15 pre-GA 接受旧客户端不兼容。
