## 旧 fail-open（测试复现的行为）
1. 策略未初始化 → `shouldEncryptOutgoingPayload` 按 plaintext 默认返回 false → 后端 strict/compliance 时静默明文发送。
2. compliance 密钥缺失/失败 → `buildE2EEData` 静默「降级为仅设备加密」，漏加审计接收方却当发送成功。
3. `ComplianceKeyService` 错误路径返回过期 stale 缓存。

## 修复后契约（typed fail-closed）
- 未初始化 + C2C/C2G → 抛 `E2eeSecurityException(policy_not_initialized)`，send/encrypt=0。
- compliance 密钥缺失/过期 → 抛 `compliance_key_unavailable`/`compliance_key_expired`，整条拒发，不用 stale cache。
- 已确认 plaintext 部署 → 不抛（明文合法）。optional 本地开关已废弃（`E2EESettings.isEnabled()` 恒 false），无 optional-on 路径，故 CB `unencrypted=true` 标记不适用（N/A，已在代码/证据说明）。
