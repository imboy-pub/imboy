# 管理端消息访问 / Admin message access

> 状态：CURRENT，描述当前后端访问规则；不代表某个候选已完成安全或交付验收。

管理端读取消息默认只返回元数据。内容读取、导出和审计写入分别受独立的服务端检查约束，前端菜单是否显示不能代替授权。

## 权限与策略

| 操作 | 权限 | 行为 |
|---|---|---|
| 列表、详情的元数据读取 | `messages:metadata:read` 或兼容键 `messages:read` | 还须通过部署策略的消息审计开关；内容字段按实际授权结果清洗 |
| 内容读取 | `messages:content:read` | 仅策略 `audit_mode=full` 时具备内容读取资格；需同时提供有效举报工单 `ticket` 和非空 `reason` |
| CSV 导出 | `messages:export` | 独立于读取权限，并受导出策略开关约束；内容仍经过相同的工单和原因检查 |

没有内容权限、策略不是 `full` 或没有正数工单 ID 时，内容按元数据口径返回。具备内容读取资格后，传入工单却缺少原因，或工单不存在，会返回错误。

当前工单检查验证工单存在，不能据此假设消息已经与工单对象做了完整的归属绑定。内容门返回服务端存储的载荷；已有 E2EE 密文不会因为管理端获得权限而在服务端解密。加密模式的适用边界见 [E2EE 政策](../compliance/e2ee-policy.md)。

## 访问审计

列表、详情和导出分别写入 `message_list_access`、`message_detail_access`、`message_export_access` 审计动作。审计上下文包含操作者、实际内容访问模式、工单和原因，以及对应请求的筛选或消息标识，不包含消息载荷。

审计写入失败时拒绝访问；导出在输出数据之前检查审计结果。排查访问失败时应同时检查角色权限、部署策略、工单参数和审计存储，而不是放宽权限来绕过失败。
