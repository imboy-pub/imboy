# ADR：隐私默认与注意力控制 v1

## 状态

Accepted for implementation

## 背景

健康社交方案需要先落一个范围清晰、可撤销、可自动化验证的切片。当前 IMBoy 已有用户在线状态设置和会话免打扰能力，但研究文档把 E2EE 默认值、动态插件市场和商业许可证状态表述得过于确定。

## 决策

### 1. 缺少设置时默认隐藏在线状态

- 服务端 user_setting 中缺少 chat_state、设置 JSON 损坏或读取失败时，按隐藏处理。
- 显式 chat_state=online 仍表示用户允许展示在线状态。
- 显式 show_online_status=true/false 的更新语义不变。
- 隐藏状态只影响状态展示和上线/下线通知，不影响真实 WebSocket 连接、消息投递、离线拉取或 ACK。

### 2. 客户端只回显服务端权威设置

客户端 show_online_status 缺失时默认显示为关闭；收到显式值后必须原样回显。客户端不得依据本地连接状态自行推断其他用户的隐私状态。

### 3. 会话免打扰保持现有契约

- isMuted > 0 时不显示本地消息弹窗。
- 未读数和 @ 未读数仍然增加。
- 消息 @ 当前用户时穿透免打扰并显示通知。
- 本轮不新增全局专注模式。

### 4. 本轮明确延期

以下项目不属于 v1：

- 将 e2ee_mode 默认改为 required；
- 服务端或插件读取 E2EE 明文；
- 关系仪表盘、关系健康评分和关系摘要；
- 动态插件下载、插件健康评分和插件市场审核制度；
- “界面隐藏但实际仍保存”的临时消息；
- 许可证、广告和商业授权策略变更。

## 验收标准

1. 后端 EUnit 覆盖缺省、显式 online、损坏设置三种状态。
2. 客户端单元测试覆盖缺失、true、false、字符串和整数编码。
3. 消息回归测试证明隐藏状态不影响投递。
4. 会话免打扰测试证明未读不丢失、@ 穿透不回归。
5. 真机验证隐私开关关闭/开启后的跨账号展示差异。

## 后续决策入口

只有 v1 全部通过后，才单独评估全局专注模式、纯客户端本地关系摘要和插件 manifest 数据权限声明。
