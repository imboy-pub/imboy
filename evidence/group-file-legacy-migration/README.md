# 历史群资料归属迁移检查

运行 `bash scripts/test/run_group_file_legacy_migration.sh`，在独立 PostgreSQL 18 容器的合成前置表结构上执行仓内原始迁移 108。空库 up/down、六条旧记录、down 后原始 metadata 逐行一致及再次 up 均通过；退出码为 0。容器及其卷已清理，不连接现有数据库，不读写对象存储。

仅群、上传者、scope 和旧存储路径全部相符的记录绑定 group_file_id；错误群、错误上传者、private scope、未知路径、非法群引用均不绑定。未匹配 group 附件仍遵循迁移原有 start_seq=1 历史聊天兼容规则，没有为它们猜测企业或群资料归属。

恢复检查使用原始 down 文件并逐行对比迁移前数据，再以原始 up 文件重新生成唯一绑定。该检查只适用于无新写入的合成迁移环境；线上 down 会删除新增的绑定列，不能当作保留迁移后业务写入的生产恢复方案。生产迁移、恢复仍需独立备份和用户授权。

这是 FILE-03 的局部证据，不证明全链迁移、真实旧文件 URL 可访问、存储对象存在或实际权限链。新上传群资料的 macOS 端到端证据另存于 App 仓。生产代码和迁移文件未改。
