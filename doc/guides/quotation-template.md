# Imboy 报价单模板（标准版 / 专业版 / 私有化源码版）

> Last Updated: 2026-03-08  
> Status: 长期销售模板文档  
> Related docs: `doc/guides/product-edition-comparison.md`, `doc/guides/product-target-boundary.md`

## 1. 使用说明

本文档用于快速生成 `Imboy` 的对外报价单。

适用场景：

1. 首次报价；
2. 版本升级报价；
3. 模块追加报价；
4. 私有化部署与定制合作报价。

本文档是模板，不直接等同于合同。最终报价应以双方确认的版本、模块、交付边界、周期和服务级别为准。

## 2. 报价单首页模板

- 项目名称：

- 销售 / 对接人：
- 有效期：建议 `7~15 天`
- 交付方式：远程交付 / 私有化部署 / 源码交付 / 定制开发

### 2.2 一句话说明

建议模板：

`Imboy` 是一套面向中小团队、私域社群和行业客户的可私有部署 IM 成品系统。本次报价基于已确认版本与模块范围，包含软件能力、交付边界与服务说明。

## 3. 报价结构建议

建议将报价拆成四层：

1. 软件版本费用；
2. 可选模块费用；
3. 实施与部署费用；
4. 维护与定制费用。

## 5. 版本报价模板

### 5.1 基础版

建议适用：

1. 需要标准 IM 能力的客户；
2. 希望快速上线验证的客户；
3. 暂不需要源码和深度定制的客户。

建议报价描述模板：

- 包含标准 IM 主包能力：登录注册、单聊、群聊、会话、未读同步、群治理、基础后台管理；
- 包含标准部署文档、基础 API 文档与基础联调支持；
- 不默认包含源码交付、深度白标和模块化扩展能力；
- 适合作为最小可上线方案。

### 5.2 专业版

建议适用：

1. 需要更完整后台治理能力的客户；
2. 需要更完整运维和审计支持的客户；
3. 已确定正式商用的项目。

建议报价描述模板：

- 在基础版之上增加完整后台治理、增强运维与审计支持；
- 可叠加 `Channel`、`E2EE` 等高配能力；
- 更适合生产级部署与正式交付；
- 可附带更明确的门禁、验收和服务边界。

### 5.3 私有化源码版

建议适用：

1. 明确需要源码交付的客户；
2. 需要深度二开、白标或行业改造的客户；
3. 有长期维护合作预期的客户。

建议报价描述模板：

- 包含源码授权、私有化部署支持和二次开发边界约定；
- 可按客户需求叠加模块化能力；
- 适合深度集成、白标和长期合作场景；
- 建议与年度维护、定制开发和 SLA 一并报价。

## 7. 实施交付报价模板

建议拆成独立报价项：

| 服务项 | 说明 | 建议报价方式 |
|---|---|---|
| 标准部署 | 单环境部署、初始化配置、启动验证 | 固定包 |
| 私有化部署 | 客户环境安装、配置、联调 | 固定包 / 按环境 |
| 联调支持 | App / 后台 / 第三方系统联调 | 按天 / 按阶段 |
| 白标配置 | Logo、名称、主题、域名、基础品牌替换 | 固定包 |
| 培训 | 产品使用、后台使用、部署培训 | 按次 |
| 驻场 / 远程支持 | 特定时段支持 | 按天 |

## 8. 维护与定制报价模板

### 8.1 年度维护

建议说明：

- 包含版本升级协助、问题排查、基础咨询与小版本修复支持；
- 不默认包含新增大功能开发；
- 可约定响应时间与沟通窗口。

### 8.2 定制开发

建议说明：

- 按人天、迭代或项目包报价；
- 需求冻结后评估周期与工作量；
- 需求变更需重新评估；
- 定制开发交付边界应单独列明。

## 9. 建议附加条款模板

### 9.1 交付边界

建议模板：

- 本次报价仅包含报价单列明的版本、模块与服务项；
- 未列明能力默认不包含；
- 未购买的二期模块默认关闭，不纳入交付验收。

### 9.2 验收条款

建议模板：

- 验收按 `Imboy 客户验收清单（一期标准版）` 或双方确认清单执行；
- 阻断项清零后进入验收通过；
- 非阻断问题进入后续修复计划，不影响交付结论。

### 9.3 服务条款

建议模板：

- 报价不默认包含长期驻场；
- 报价不默认包含第三方服务费用；
- 第三方服务采购由客户承担或单独报价；
- 生产环境运维责任边界需在合同中明确。
